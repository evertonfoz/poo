# Mini Projeto com Interfaces e Serviços: Implementações Concretas para Emissão, Registro e Notificação de Certificados

## Objetivo do material

Neste material, você aprenderá a transformar interfaces em classes concretas dentro de um mini projeto de certificados. A etapa estudada corresponde à criação das implementações responsáveis por emitir certificados, registrar emissões e enviar notificações. O foco é compreender como uma interface define um contrato e como diferentes classes podem cumprir esse contrato de maneiras distintas. 

Ao final, você deverá ser capaz de:

* identificar quais classes implementam cada interface;
* criar múltiplas implementações para o mesmo contrato;
* entender por que interfaces tornam o projeto mais flexível;
* validar se as classes concretas cumprem corretamente suas interfaces;
* preparar o projeto para uma próxima etapa, em que um serviço principal coordenará essas implementações.

---

# 1. Contextualização do problema

Em um sistema de certificados, normalmente existem várias responsabilidades diferentes. Um certificado precisa ser emitido, registrado e, muitas vezes, comunicado ao aluno ou destinatário. Essas responsabilidades podem parecer simples, mas cada uma delas pode ter várias formas de execução.

Por exemplo, um certificado pode ser emitido em PDF, em HTML, em texto simples ou enviado para outro sistema. O registro da emissão pode aparecer no console, ser salvo em memória, persistido em banco de dados ou enviado para um serviço externo. A notificação pode ser feita por e-mail, SMS ou outro canal.

Se o sistema fosse construído diretamente com uma única classe para cada comportamento, ele ficaria rígido. Uma mudança simples, como trocar emissão em PDF por emissão em HTML, poderia exigir alterações em várias partes do código. As interfaces ajudam a evitar esse problema porque separam o contrato do comportamento concreto.

Uma interface diz o que uma classe precisa fazer. A classe concreta define como isso será feito.

Neste mini projeto, o foco é criar classes concretas para três contratos já existentes:

```csharp
IEmissorDeCertificado
IRegistroDeCertificado
INotificador
```

Essas interfaces representam os comportamentos esperados no projeto de certificados. Agora, a tarefa é criar classes que implementem esses contratos.

# 3. Conceitos fundamentais

## 3.1 Interface

Uma interface é um contrato. Ela define quais métodos uma classe precisa possuir, mas não define como esses métodos serão executados.

Observe o contrato para emissão de certificado:

```csharp
public interface IEmissorDeCertificado
{
    void Emitir(Certificado certificado);
}
```

Essa interface afirma que qualquer classe emissora de certificado precisa ter um método chamado `Emitir`, que recebe um objeto do tipo `Certificado` e não retorna nenhum valor.

A interface não diz se o certificado será emitido em PDF, HTML, texto ou outro formato. Ela apenas diz que a classe deve saber emitir um certificado.

## 3.2 Classe concreta

Uma classe concreta é uma classe que realmente executa um comportamento. Quando uma classe implementa uma interface, ela assume o compromisso de fornecer todos os métodos definidos no contrato.

Exemplo:

```csharp
public class EmissorCertificadoPdf : IEmissorDeCertificado
{
    public void Emitir(Certificado certificado)
    {
        Console.WriteLine("Emitindo certificado em PDF...");
        Console.WriteLine(certificado.ObterResumo());
    }
}
```

A classe `EmissorCertificadoPdf` implementa `IEmissorDeCertificado`. Por isso, ela precisa ter o método `Emitir`.

## 3.3 Contrato e implementação

A diferença entre contrato e implementação é central neste projeto.

O contrato define a obrigação. A implementação define a execução.

No caso da emissão de certificados:

```csharp
IEmissorDeCertificado
```

é o contrato.

As classes abaixo são implementações concretas:

```csharp
EmissorCertificadoPdf
EmissorCertificadoHtml
```

As duas sabem emitir certificados, mas cada uma emite de uma forma diferente.

# 4. Contratos que serão implementados

## 4.1 Contrato de emissão de certificado

```csharp
public interface IEmissorDeCertificado
{
    void Emitir(Certificado certificado);
}
```

Esse contrato define que uma classe emissora deve saber emitir um certificado.

Uma classe que implementa essa interface precisa obrigatoriamente possuir este método:

```csharp
void Emitir(Certificado certificado);
```

O parâmetro `certificado` representa o certificado que será emitido. O método não retorna valor porque sua responsabilidade é executar uma ação.

## 4.2 Contrato de registro de certificado

```csharp
public interface IRegistroDeCertificado
{
    void Registrar(Certificado certificado);
}
```

Esse contrato define que uma classe registradora deve saber registrar um certificado emitido.

A interface não define onde o certificado será registrado. Ele pode ser exibido no console, guardado em uma lista em memória, salvo em arquivo, enviado para banco de dados ou encaminhado para outro sistema.

## 4.3 Contrato de notificação

```csharp
public interface INotificador
{
    void Enviar(string destinatario, string mensagem);
}
```

Esse contrato define que uma classe notificadora deve saber enviar uma mensagem para um destinatário.

O método recebe duas informações:

```csharp
string destinatario
string mensagem
```

O destinatário indica para quem a mensagem será enviada. A mensagem representa o conteúdo da notificação. A interface não define o canal. O envio pode ser por e-mail, SMS ou outro meio.

# 5. Implementando emissão em PDF

A primeira implementação concreta será responsável por emitir um certificado em PDF. Neste mini projeto, a emissão será simulada no console. O objetivo não é gerar um arquivo PDF real, mas representar a responsabilidade da classe.

Arquivo:

```text
EmissorCertificadoPdf.cs
```

Código:

```csharp
using MiniProjetoCertificados.Entidades;
using MiniProjetoCertificados.Interfaces;

namespace MiniProjetoCertificados.Implementacoes;

public class EmissorCertificadoPdf : IEmissorDeCertificado
{
    public void Emitir(Certificado certificado)
    {
        Console.WriteLine("Emitindo certificado em PDF...");
        Console.WriteLine(certificado.ObterResumo());
    }
}
```

A primeira parte do código importa os namespaces necessários:

```csharp
using MiniProjetoCertificados.Entidades;
using MiniProjetoCertificados.Interfaces;
```

O namespace `Entidades` é necessário porque o método `Emitir` recebe um objeto do tipo `Certificado`. O namespace `Interfaces` é necessário porque a classe implementa `IEmissorDeCertificado`.

A declaração da classe é:

```csharp
public class EmissorCertificadoPdf : IEmissorDeCertificado
```

O sinal de dois-pontos indica que a classe `EmissorCertificadoPdf` implementa a interface `IEmissorDeCertificado`.

O método obrigatório é:

```csharp
public void Emitir(Certificado certificado)
```

Esse método cumpre o contrato da interface. Dentro dele, o sistema exibe uma mensagem indicando a emissão em PDF e depois imprime o resumo do certificado.

```csharp
Console.WriteLine(certificado.ObterResumo());
```

O método `ObterResumo()` pertence ao certificado e retorna uma representação textual dos dados principais. Isso evita que a classe emissora precise montar manualmente todos os dados do certificado.

# 6. Implementando emissão em HTML

Agora será criada uma segunda forma de emissão. A emissão em HTML representa uma saída formatada com tags, como se o certificado pudesse ser exibido em uma página web.

Arquivo:

```text
EmissorCertificadoHtml.cs
```

Código:

```csharp
using MiniProjetoCertificados.Entidades;
using MiniProjetoCertificados.Interfaces;

namespace MiniProjetoCertificados.Implementacoes;

public class EmissorCertificadoHtml : IEmissorDeCertificado
{
    public void Emitir(Certificado certificado)
    {
        Console.WriteLine("Emitindo certificado em HTML...");
        Console.WriteLine("<h1>Certificado de " +
            $"{certificado.Aluno.Nome}</h1>");
        Console.WriteLine($"<p>Curso: {certificado.Curso.Nome}</p>");
        Console.WriteLine("<p>Carga horária: " +
            $"{certificado.Curso.CargaHoraria} horas</p>");
        Console.WriteLine("<p>Código: " +
            $"{certificado.CodigoVerificacao}</p>");
    }
}
```

Essa classe também implementa `IEmissorDeCertificado`. Portanto, ela também precisa possuir o método `Emitir`.

A diferença está no comportamento interno. Em vez de usar `certificado.ObterResumo()`, a classe monta uma saída parecida com HTML:

```csharp
Console.WriteLine("<h1>Certificado de " +
    $"{certificado.Aluno.Nome}</h1>");
```

Esse trecho exibe o nome do aluno dentro de uma tag `<h1>`, que normalmente representa um título em HTML.

Depois, a classe imprime o nome do curso:

```csharp
Console.WriteLine($"<p>Curso: {certificado.Curso.Nome}</p>");
```

Também imprime a carga horária:

```csharp
Console.WriteLine("<p>Carga horária: " +
    $"{certificado.Curso.CargaHoraria} horas</p>");
```

E, por fim, imprime o código de verificação:

```csharp
Console.WriteLine("<p>Código: " +
    $"{certificado.CodigoVerificacao}</p>");
```

A emissão em HTML mostra que o mesmo contrato pode gerar uma saída diferente. O sistema continua chamando `Emitir`, mas o resultado visual muda conforme a implementação escolhida.

# 12. Implementando registro em memória

A segunda implementação de registro guarda os certificados em uma lista interna. Essa abordagem é diferente do console porque mantém os objetos registrados durante a execução do programa.

Arquivo:

```text
RegistroCertificadoMemoria.cs
```

Código:

```csharp
using MiniProjetoCertificados.Entidades;
using MiniProjetoCertificados.Interfaces;

namespace MiniProjetoCertificados.Implementacoes;

public class RegistroCertificadoMemoria : IRegistroDeCertificado
{
    private readonly List<Certificado> _certificados = new();

    public IReadOnlyCollection<Certificado> Certificados =>
        _certificados.AsReadOnly();

    public void Registrar(Certificado certificado)
    {
        if (certificado is null)
        {
            throw new ArgumentNullException(nameof(certificado));
        }

        _certificados.Add(certificado);
        Console.WriteLine("Certificado registrado em memória.");
    }
}
```

Essa classe é mais elaborada que o registro no console. Ela possui uma lista interna:

```csharp
private readonly List<Certificado> _certificados = new();
```

A palavra-chave `private` indica que a lista só pode ser acessada dentro da própria classe. Isso impede que outras partes do sistema modifiquem diretamente a coleção.

A palavra-chave `readonly` indica que a referência da lista não deve ser trocada depois de inicializada. Ainda é possível adicionar itens à lista, mas a variável `_certificados` não deve passar a apontar para outra lista.

A propriedade pública é:

```csharp
public IReadOnlyCollection<Certificado> Certificados =>
    _certificados.AsReadOnly();
```

Essa propriedade permite consultar os certificados registrados sem expor a lista original. Isso é importante porque, se a lista original fosse exposta diretamente, outras classes poderiam adicionar, remover ou alterar elementos sem passar pelo método `Registrar`.

O método `Registrar` começa validando se o certificado recebido é nulo:

```csharp
if (certificado is null)
{
    throw new ArgumentNullException(nameof(certificado));
}
```

Essa validação protege a classe contra registros inválidos. Se o certificado for nulo, a classe lança uma exceção informando o problema.

Depois da validação, o certificado é adicionado à lista:

```csharp
_certificados.Add(certificado);
```

Por fim, uma mensagem é exibida:

```csharp
Console.WriteLine("Certificado registrado em memória.");
```

# 13. Por que proteger a lista interna?

A proteção da lista interna é uma decisão importante de projeto.

Compare estas duas possibilidades.

Exposição perigosa:

```csharp
public List<Certificado> Certificados = new();
```

Nesse caso, qualquer parte do sistema poderia acessar a lista e modificá-la diretamente:

```csharp
registro.Certificados.Clear();
```

Isso poderia apagar todos os certificados registrados sem passar por nenhuma regra da classe.

Agora observe a abordagem protegida:

```csharp
private readonly List<Certificado> _certificados = new();

public IReadOnlyCollection<Certificado> Certificados =>
    _certificados.AsReadOnly();
```

Aqui, a lista original fica privada. O restante do sistema consegue consultar os certificados, mas não consegue modificar diretamente a coleção interna.

Isso mantém o controle dentro da própria classe. Para registrar um certificado, o caminho correto é chamar:

```csharp
Registrar(certificado)
```

Essa decisão preserva a integridade dos dados.

# 15. Diferenças conceituais importantes

## 15.1 Interface não é implementação

A interface não executa o comportamento final. Ela define quais métodos devem existir.

Exemplo:

```csharp
public interface INotificador
{
    void Enviar(string destinatario, string mensagem);
}
```

Esse código não envia e-mail, SMS ou qualquer outra mensagem. Ele apenas define que uma classe notificadora precisa ter o método `Enviar`.

Quem executa o comportamento é a classe concreta:

```csharp
public class EmailNotificador : INotificador
```

## 15.2 Mesmo contrato não significa mesmo comportamento

Duas classes podem implementar a mesma interface e ainda assim se comportar de formas diferentes.

Exemplo:

```csharp
EmissorCertificadoPdf
EmissorCertificadoHtml
```

As duas implementam:

```csharp
IEmissorDeCertificado
```

Mas uma usa o resumo do certificado e a outra monta uma saída em HTML.

## 15.3 Flexibilidade não significa desorganização

Criar várias implementações não significa duplicar código sem motivo. A ideia é representar comportamentos realmente diferentes para o mesmo contrato.

Neste projeto, faz sentido ter mais de uma implementação porque existem diferentes formas de emitir, notificar e registrar certificados.

## Possíveis erros

Um erro comum é declarar que a classe implementa uma interface, mas esquecer o método obrigatório. Por exemplo:

```csharp
public class SmsNotificador : INotificador
{
}
```

Esse código não compila porque `INotificador` exige o método `Enviar`.

Outro erro comum é alterar a assinatura do método. Por exemplo:

```csharp
public void Enviar(string mensagem)
```

Esse método não cumpre o contrato porque a interface exige dois parâmetros:

```csharp
void Enviar(string destinatario, string mensagem);
```

A assinatura precisa ser compatível com a interface.

O projeto não compila. Em C#, quando uma classe declara que implementa uma interface, ela precisa fornecer todos os membros exigidos por essa interface. Caso contrário, o compilador aponta erro.

## 17.8 Por que interfaces permitem criar diferentes implementações para o mesmo comportamento?

Porque a interface define apenas o contrato, não a forma de execução. Assim, várias classes podem cumprir o mesmo contrato com comportamentos diferentes. Isso permite trocar implementações sem mudar a ideia principal do sistema.

# 18. Erros comuns e como corrigir

## 18.1 Esquecer de importar o namespace da interface

Erro comum:

```csharp
public class EmailNotificador : INotificador
```

mas o arquivo não possui:

```csharp
using MiniProjetoCertificados.Interfaces;
```

Sem o `using`, o compilador pode não encontrar a interface.

A correção é importar o namespace correto ou escrever o nome completo da interface.

## 18.2 Esquecer de importar o namespace da entidade

Classes que recebem `Certificado` precisam acessar a entidade:

```csharp
using MiniProjetoCertificados.Entidades;
```

Sem esse `using`, o compilador pode não reconhecer o tipo `Certificado`.

## 18.3 Alterar a assinatura do método da interface

A interface exige uma assinatura específica. Se a interface define:

```csharp
void Registrar(Certificado certificado);
```

a classe não pode implementar apenas:

```csharp
void Registrar()
```

ou:

```csharp
void Registrar(string codigo)
```

Esses métodos não cumprem o contrato.

## 18.4 Expor diretamente a lista interna

Em `RegistroCertificadoMemoria`, expor a lista diretamente seria perigoso:

```csharp
public List<Certificado> Certificados { get; set; }
```

Isso permitiria que outras classes alterassem a lista sem controle. A forma mais segura é manter a lista privada e expor uma visão somente leitura.

## 18.5 Confundir simulação com funcionalidade real

Neste mini projeto, a emissão em PDF e o envio de e-mail ou SMS são simulados com `Console.WriteLine`. Isso não gera um PDF real nem envia uma mensagem real. A simulação serve para estudar responsabilidades, contratos e implementações.
