# Criando e Implementando Interfaces em C#: contratos de comportamento para sistemas flexíveis

Material autossuficiente elaborado a partir do conteúdo-base sobre criação, implementação e uso de interfaces em C#. 

## Objetivo do material

Neste material, você aprenderá a criar interfaces em C#, implementar contratos em classes concretas e usar objetos por meio de referências do tipo da interface.

Ao final, você deverá ser capaz de:

1. Declarar uma interface usando a palavra-chave `interface`.
2. Definir métodos que representam comportamentos obrigatórios.
3. Criar classes que implementam todos os membros exigidos pela interface.
4. Usar uma interface como tipo de variável.
5. Entender por que interfaces tornam o código mais flexível, organizado e menos dependente de classes concretas.
6. Reconhecer erros comuns de implementação, como assinatura incorreta, método ausente ou interface grande demais.

---

## 1. Contextualização: por que interfaces são importantes?

Imagine um sistema que precisa exportar informações em vários formatos. O conteúdo pode ser exportado em CSV, JSON, texto simples ou HTML.

Cada formato possui uma estrutura própria:

CSV organiza dados separados por vírgula ou ponto e vírgula.

JSON usa chaves, nomes de propriedades e valores.

Texto simples apresenta uma mensagem legível diretamente.

HTML estrutura o conteúdo com tags de marcação.

Apesar das diferenças, todos esses formatos têm uma responsabilidade em comum: exportar conteúdo.

Quando várias classes diferentes possuem o mesmo comportamento esperado, é possível representar esse comportamento por meio de uma interface.

A interface não define os detalhes da execução. Ela define apenas o contrato: aquilo que toda classe participante precisa oferecer.

Em outras palavras:

```csharp
A interface define o que deve existir.
A classe concreta define como isso será feito.
```

Esse recurso é importante porque permite escrever códigos mais flexíveis. Em vez de depender diretamente de uma classe específica, o sistema pode depender de um contrato comum. Assim, diferentes implementações podem ser usadas sem alterar a lógica principal.

## 2. Conceito fundamental: interface como contrato de comportamento

Uma interface é um tipo que define um conjunto de membros obrigatórios, normalmente métodos, propriedades ou eventos.

Neste material, o foco será em métodos.

Quando uma classe implementa uma interface, ela assume o compromisso de fornecer todos os membros definidos por essa interface.

Observe a seguinte interface:

```csharp
public interface IExportador
{
    void Exportar(string conteudo);
}
```

Essa interface se chama `IExportador`.

Ela declara um método chamado `Exportar`.

O método recebe um parâmetro chamado `conteudo`, do tipo `string`.

O método não retorna valor, por isso usa `void`.

Essa interface estabelece o seguinte contrato:

Toda classe que implementar `IExportador` deverá possuir um método público chamado `Exportar`, que recebe uma `string` como parâmetro e não retorna valor.

A interface não informa se o conteúdo será exportado em CSV, JSON, HTML ou texto simples. Essa decisão pertence às classes concretas.

## 3. Estrutura básica de uma interface em C#

A estrutura geral de uma interface em C# é:

```csharp
public interface NomeDaInterface
{
    TipoDeRetorno NomeDoMetodo(Parametros);
}
```

Cada parte tem uma função específica.

`public` indica que a interface pode ser acessada por outras partes do projeto.

`interface` é a palavra-chave usada para declarar uma interface.

`NomeDaInterface` é o nome do contrato. Em C#, é comum que nomes de interfaces comecem com a letra `I`, como `IExportador`, `ICalculadoraDeDesconto` ou `IAutenticador`.

Dentro das chaves, aparecem as assinaturas dos métodos exigidos.

A assinatura de um método inclui:

```csharp
Tipo de retorno + Nome do método + Parâmetros
```

Por exemplo:

```csharp
void Exportar(string conteudo);
```

Essa linha informa que toda classe implementadora precisa ter um método chamado `Exportar`, que recebe uma `string` e não retorna nada.

Observe que o método na interface não possui corpo:

```csharp
public interface IExportador
{
    void Exportar(string conteudo);
}
```

Não há chaves após `Exportar`. Não existe implementação ali. A interface apenas declara a obrigação.

## 4. Criando uma classe que implementa uma interface

Para implementar uma interface, a classe usa o símbolo `:` depois do nome da classe.

Exemplo:

```csharp
public class ExportadorCsv : IExportador
{
    public void Exportar(string conteudo)
    {
        Console.WriteLine($"Exportando em CSV: {conteudo}");
    }
}
```

Nesse código, `ExportadorCsv` é uma classe concreta.

A expressão `: IExportador` indica que a classe implementa a interface `IExportador`.

Isso significa que `ExportadorCsv` precisa fornecer o método:

```csharp
public void Exportar(string conteudo)
```

O método precisa ser público porque outras partes do sistema precisam conseguir chamá-lo por meio da interface.

A implementação concreta aparece dentro do método:

```csharp
Console.WriteLine($"Exportando em CSV: {conteudo}");
```

Essa linha representa uma forma simples de exportar o conteúdo. Em um sistema real, a exportação poderia gerar um arquivo, enviar dados para outro serviço ou salvar informações em algum local.

## 5. Mesmo contrato, implementações diferentes

Uma das principais vantagens da interface é permitir que várias classes cumpram o mesmo contrato de formas diferentes.

Veja duas implementações da interface `IExportador`.

### ExportadorCsv

```csharp
public class ExportadorCsv : IExportador
{
    public void Exportar(string conteudo)
    {
        Console.WriteLine($"Exportando em CSV: {conteudo}");
    }
}
```

Essa classe exporta o conteúdo simulando o formato CSV.

Exemplo de conteúdo:

```csharp
"Clara;Engenharia;9.5"
```

Resultado esperado:

```text
Exportando em CSV: Clara;Engenharia;9.5
```

### ExportadorJson

```csharp
public class ExportadorJson : IExportador
{
    public void Exportar(string conteudo)
    {
        Console.WriteLine($"{{ \"conteudo\": \"{conteudo}\" }}");
    }
}
```

Essa classe também implementa `IExportador`, mas sua saída simula um formato JSON.

Exemplo de conteúdo:

```csharp
"Clara - Engenharia - 9.5"
```

Resultado esperado:

```text
{ "conteudo": "Clara - Engenharia - 9.5" }
```

As duas classes cumprem o mesmo contrato:

```csharp
void Exportar(string conteudo);
```

Mas cada uma executa o comportamento de uma maneira.

Esse é um ponto central das interfaces: o código pode tratar diferentes objetos como exportadores, sem precisar conhecer todos os detalhes internos de cada classe.

## 6. Usando a interface como tipo de variável

Uma interface pode ser usada como tipo de variável. Isso permite que a variável receba qualquer objeto que implemente aquele contrato.

### Uso com classe concreta

```csharp
ExportadorCsv exportador = new ExportadorCsv();
exportador.Exportar("Clara;Engenharia;9.5");
```

Esse código funciona, mas a variável está diretamente ligada à classe `ExportadorCsv`.

Isso significa que, se o sistema precisar usar `ExportadorJson`, será necessário alterar o tipo da variável.

### Uso com interface

```csharp
IExportador exportador = new ExportadorCsv();
exportador.Exportar("Clara;Engenharia;9.5");
```

Agora a variável é do tipo `IExportador`.

Isso quer dizer que ela aceita qualquer objeto que implemente `IExportador`.

Por exemplo:

```csharp
IExportador exportador = new ExportadorJson();
exportador.Exportar("Clara - Engenharia - 9.5");
```

A variável continua sendo do tipo `IExportador`, mas o objeto concreto mudou.

A leitura correta dessa linha é:

```csharp
IExportador exportador = new ExportadorCsv();
```

Crie uma variável chamada `exportador` que aceita qualquer objeto capaz de cumprir o contrato `IExportador`. Neste momento, o objeto concreto usado será `ExportadorCsv`.

E nesta linha:

```csharp
IExportador exportador = new ExportadorJson();
```

Crie uma variável chamada `exportador` que aceita qualquer objeto capaz de cumprir o contrato `IExportador`. Neste momento, o objeto concreto usado será `ExportadorJson`.

O tipo da variável representa o contrato. O objeto criado representa a implementação concreta.

## 7. Três classes, um contrato

Podemos ter várias classes concretas implementando a mesma interface.

```csharp
public class ExportadorTexto : IExportador
{
    public void Exportar(string conteudo)
    {
        Console.WriteLine($"Texto simples: {conteudo}");
    }
}
```

Agora temos três implementações:

```csharp
IExportador exportadorCsv = new ExportadorCsv();
IExportador exportadorJson = new ExportadorJson();
IExportador exportadorTexto = new ExportadorTexto();
```

Todas as variáveis são do tipo `IExportador`.

Cada objeto concreto executa `Exportar` de sua própria forma.

```csharp
exportadorCsv.Exportar("Clara;Engenharia;9.5");
exportadorJson.Exportar("Clara - Engenharia - 9.5");
exportadorTexto.Exportar("Clara cursa Engenharia e obteve nota 9.5.");
```

Resultado esperado:

```text
Exportando em CSV: Clara;Engenharia;9.5
{ "conteudo": "Clara - Engenharia - 9.5" }
Texto simples: Clara cursa Engenharia e obteve nota 9.5.
```

O contrato é o mesmo. A execução muda conforme a classe concreta.

## 8. Implementação obrigatória de todos os membros

Quando uma classe declara que implementa uma interface, ela precisa implementar todos os membros exigidos por essa interface.

Considere novamente a interface:

```csharp
public interface IExportador
{
    void Exportar(string conteudo);
}
```

A classe abaixo está incorreta:

```csharp
public class ExportadorHtml : IExportador
{
    // Método Exportar ausente.
}
```

Essa classe declara que implementa `IExportador`, mas não fornece o método `Exportar`.

O código não compila porque o contrato não foi cumprido.

A implementação correta seria:

```csharp
public class ExportadorHtml : IExportador
{
    public void Exportar(string conteudo)
    {
        Console.WriteLine($"<p>{conteudo}</p>");
    }
}
```

Agora a classe possui o método exigido:

```csharp
public void Exportar(string conteudo)
```

Portanto, cumpre o contrato definido pela interface.

---

## 9. A assinatura do método precisa ser compatível

Não basta criar um método com nome parecido. A assinatura precisa corresponder ao que foi definido na interface.

A interface define:

```csharp
void Exportar(string conteudo);
```

A implementação abaixo está incorreta:

```csharp
public class ExportadorTexto : IExportador
{
    public void Exportar()
    {
        Console.WriteLine("Conteúdo");
    }
}
```

O problema é que o método `Exportar` não recebe o parâmetro `string conteudo`.

A interface exige:

```csharp
Exportar(string conteudo)
```

Mas a classe implementou:

```csharp
Exportar()
```

Esses métodos têm assinaturas diferentes.

A implementação correta é:

```csharp
public class ExportadorTexto : IExportador
{
    public void Exportar(string conteudo)
    {
        Console.WriteLine(conteudo);
    }
}
```

Para cumprir o contrato, a classe precisa respeitar:

Nome do método.

Tipo de retorno.

Quantidade de parâmetros.

Tipo dos parâmetros.

Ordem dos parâmetros.

## 10. Interface com método que retorna valor

Interfaces também podem definir métodos que retornam valores.

Considere uma calculadora de desconto:

```csharp
public interface ICalculadoraDeDesconto
{
    decimal Calcular(decimal valor);
}
```

Essa interface declara que toda calculadora de desconto precisa ter um método chamado `Calcular`.

Esse método recebe um valor do tipo `decimal`.

Esse método retorna um valor do tipo `decimal`.

O tipo `decimal` é muito usado para valores monetários, pois representa números decimais com boa precisão para cálculos financeiros.

### Implementação de desconto padrão

```csharp
public class CalculadoraDescontoPadrao : ICalculadoraDeDesconto
{
    public decimal Calcular(decimal valor)
    {
        return valor * 0.05m;
    }
}
```

Essa implementação calcula 5% de desconto.

Se o valor for `200m`, o desconto será:

```text
200 * 0.05 = 10
```

### Implementação de desconto para cliente VIP

```csharp
public class CalculadoraDescontoClienteVip : ICalculadoraDeDesconto
{
    public decimal Calcular(decimal valor)
    {
        return valor * 0.15m;
    }
}
```

Essa implementação calcula 15% de desconto.

Se o valor for `200m`, o desconto será:

```text
200 * 0.15 = 30
```

### Uso no código

```csharp
ICalculadoraDeDesconto calculadora = new CalculadoraDescontoClienteVip();

decimal desconto = calculadora.Calcular(200m);

Console.WriteLine($"Desconto: R$ {desconto:F2}");
```

Resultado esperado:

```text
Desconto: R$ 30,00
```

A interface define o comportamento de calcular desconto. Cada classe concreta define a regra específica.

## 11. Interface com mais de um método

Uma interface pode conter mais de um método.

Exemplo:

```csharp
public interface IAutenticador
{
    bool Autenticar(string usuario, string senha);
    void EncerrarSessao(string usuario);
}
```

Essa interface define dois comportamentos obrigatórios:

`Autenticar`, que recebe usuário e senha, e retorna `true` ou `false`.

`EncerrarSessao`, que recebe o nome do usuário e não retorna valor.

Uma implementação completa seria:

```csharp
public class AutenticadorLocal : IAutenticador
{
    public bool Autenticar(string usuario, string senha)
    {
        return usuario == "admin" && senha == "123";
    }

    public void EncerrarSessao(string usuario)
    {
        Console.WriteLine($"Sessão encerrada: {usuario}.");
    }
}
```

Uso:

```csharp
IAutenticador autenticador = new AutenticadorLocal();

bool autenticado = autenticador.Autenticar("admin", "123");

if (autenticado)
{
    Console.WriteLine("Usuário autenticado.");
    autenticador.EncerrarSessao("admin");
}
else
{
    Console.WriteLine("Usuário ou senha inválidos.");
}
```

Resultado esperado:

```text
Usuário autenticado.
Sessão encerrada: admin.
```

Se a classe implementar apenas um dos métodos, o contrato estará incompleto e o código não compilará.

## 12. Cuidado com interfaces grandes demais

Embora seja possível criar interfaces com vários métodos, isso deve ser feito com cuidado.

Uma interface muito grande pode misturar responsabilidades diferentes e obrigar classes a implementar métodos que não fazem sentido para elas.

Observe o exemplo problemático:

```csharp
public interface IGerenciadorAcademico
{
    void CadastrarEstudante(string nome);
    void CadastrarProfessor(string nome);
    void EmitirHistorico(string estudante);
    void GerarFolhaPagamento();
    void EnviarEmail(string destinatario, string mensagem);
}
```

Essa interface mistura muitas responsabilidades:

Cadastro de estudantes.

Cadastro de professores.

Emissão de histórico.

Geração de folha de pagamento.

Envio de e-mail.

O problema é que uma classe responsável apenas por emitir históricos poderia ser obrigada a implementar métodos relacionados a folha de pagamento ou envio de e-mail.

Isso torna o contrato confuso e difícil de manter.

Uma abordagem melhor é separar os contratos:

```csharp
public interface ICadastroDeEstudante
{
    void CadastrarEstudante(string nome);
}
```

```csharp
public interface IEmissorDeHistorico
{
    void EmitirHistorico(string estudante);
}
```

```csharp
public interface INotificador
{
    void Enviar(string destinatario, string mensagem);
}
```

Interfaces menores deixam o sistema mais claro.

Cada interface representa uma responsabilidade específica.

Esse cuidado segue uma ideia importante de design: contratos devem ser coesos, ou seja, devem agrupar comportamentos que realmente pertencem ao mesmo papel.

## 13. Uma classe pode implementar mais de uma interface

Uma classe pode cumprir mais de um contrato ao mesmo tempo.

Isso é útil quando ela realmente possui mais de uma responsabilidade compatível com seu papel.

Considere duas interfaces:

```csharp
public interface IExportador
{
    void Exportar(string conteudo);
}
```

```csharp
public interface ICompactador
{
    void Compactar(string arquivo);
}
```

Agora veja uma classe que implementa as duas:

```csharp
public class ExportadorZip : IExportador, ICompactador
{
    public void Exportar(string conteudo)
    {
        Console.WriteLine($"Exportando conteúdo: {conteudo}");
    }

    public void Compactar(string arquivo)
    {
        Console.WriteLine($"Compactando arquivo: {arquivo}");
    }
}
```

A classe `ExportadorZip` implementa dois contratos:

`IExportador`, porque sabe exportar conteúdo.

`ICompactador`, porque sabe compactar arquivo.

Por isso, ela precisa implementar os dois métodos:

```csharp
public void Exportar(string conteudo)
```

e

```csharp
public void Compactar(string arquivo)
```

## 14. A mesma classe vista por diferentes contratos

Quando uma classe implementa mais de uma interface, ela pode ser usada por diferentes tipos de referência.

### Referência pela classe concreta

```csharp
ExportadorZip zip = new ExportadorZip();

zip.Exportar("Relatório mensal");
zip.Compactar("relatorio.txt");
```

Quando a variável é do tipo `ExportadorZip`, o código enxerga todos os métodos públicos da classe.

Resultado esperado:

```text
Exportando conteúdo: Relatório mensal
Compactando arquivo: relatorio.txt
```

### Referência pela interface IExportador

```csharp
IExportador exportador = new ExportadorZip();

exportador.Exportar("Relatório mensal");
```

Quando a variável é do tipo `IExportador`, o código enxerga apenas os membros do contrato `IExportador`.

Nesse caso, o método `Compactar` não fica disponível por essa referência.

### Referência pela interface ICompactador

```csharp
ICompactador compactador = new ExportadorZip();

compactador.Compactar("relatorio.txt");
```

Quando a variável é do tipo `ICompactador`, o código enxerga apenas os membros do contrato `ICompactador`.

A interface funciona como uma visão específica sobre o objeto.

O mesmo objeto concreto pode ser visto como exportador, como compactador ou como a classe completa, dependendo do tipo da variável usada.

## 15. Exemplo completo: exportadores organizados por interface

A seguir está um exemplo completo com interface, implementações e uso no `Program.cs`.

### Interface IExportador

Arquivo sugerido: `Interfaces/IExportador.cs`

```csharp
public interface IExportador
{
    void Exportar(string conteudo);
}
```

Essa interface define o contrato comum para todos os exportadores.

Qualquer classe que implemente `IExportador` precisa fornecer o método `Exportar`.

### Classe ExportadorCsv

Arquivo sugerido: `Exportadores/ExportadorCsv.cs`

```csharp
public class ExportadorCsv : IExportador
{
    public void Exportar(string conteudo)
    {
        Console.WriteLine($"Exportando em CSV: {conteudo}");
    }
}
```

Essa classe representa uma exportação no formato CSV.

### Classe ExportadorJson

Arquivo sugerido: `Exportadores/ExportadorJson.cs`

```csharp
public class ExportadorJson : IExportador
{
    public void Exportar(string conteudo)
    {
        Console.WriteLine($"{{ \"conteudo\": \"{conteudo}\" }}");
    }
}
```

Essa classe representa uma exportação no formato JSON.

### Classe ExportadorHtml

Arquivo sugerido: `Exportadores/ExportadorHtml.cs`

```csharp
public class ExportadorHtml : IExportador
{
    public void Exportar(string conteudo)
    {
        Console.WriteLine($"<p>{conteudo}</p>");
    }
}
```

Essa classe representa uma exportação em HTML simples.

### Program.cs

```csharp
IExportador exportador = new ExportadorCsv();
exportador.Exportar("Clara;Computação;9.5");

exportador = new ExportadorJson();
exportador.Exportar("Clara - Computação - 9.5");

exportador = new ExportadorHtml();
exportador.Exportar("Clara - Computação - 9.5");
```

Resultado esperado:

```text
Exportando em CSV: Clara;Computação;9.5
{ "conteudo": "Clara - Computação - 9.5" }
<p>Clara - Computação - 9.5</p>
```

A variável `exportador` continua sendo do tipo `IExportador`.

O objeto concreto muda ao longo do código.

O método chamado continua sendo `Exportar`.

Isso demonstra a flexibilidade obtida ao programar usando o contrato em vez de depender diretamente de uma classe específica.

## 16. Organização sugerida do projeto

Uma organização simples para esse exemplo seria:

```text
Projeto
|
├── Interfaces
│   └── IExportador.cs
|
├── Exportadores
│   ├── ExportadorCsv.cs
│   ├── ExportadorJson.cs
│   └── ExportadorHtml.cs
|
└── Program.cs
```

A pasta `Interfaces` contém os contratos.

A pasta `Exportadores` contém as classes concretas que implementam esses contratos.

O arquivo `Program.cs` contém o código de uso.

Essa separação ajuda a manter o projeto mais organizado. Em projetos maiores, separar contratos e implementações facilita manutenção, leitura e evolução do sistema.

## 17. Aplicação prática resolvida: emissão de documentos acadêmicos

### Cenário

Um sistema acadêmico precisa emitir diferentes documentos para estudantes.

Os documentos podem ser:

Declaração de matrícula.

Histórico escolar.

Certificado de conclusão.

Cada documento tem um conteúdo diferente, mas todos compartilham o mesmo comportamento principal: emitir um documento para um estudante.

### Objetivo

Criar uma interface que represente o contrato de emissão de documento e implementar três classes concretas, cada uma responsável por emitir um tipo de documento.

### Solução completa

#### Interface IEmissorDeDocumento

```csharp
public interface IEmissorDeDocumento
{
    void Emitir(string nomeEstudante);
}
```

Essa interface define que todo emissor de documento precisa ter um método chamado `Emitir`.

O método recebe o nome do estudante e não retorna valor.

#### Classe EmissorDeclaracaoMatricula

```csharp
public class EmissorDeclaracaoMatricula : IEmissorDeDocumento
{
    public void Emitir(string nomeEstudante)
    {
        Console.WriteLine($"Declaração de matrícula: {nomeEstudante} está regularmente matriculado.");
    }
}
```

Essa classe cumpre o contrato `IEmissorDeDocumento`.

Sua implementação emite uma declaração de matrícula.

#### Classe EmissorHistoricoEscolar

```csharp
public class EmissorHistoricoEscolar : IEmissorDeDocumento
{
    public void Emitir(string nomeEstudante)
    {
        Console.WriteLine($"Histórico escolar emitido para: {nomeEstudante}.");
    }
}
```

Essa classe também cumpre o mesmo contrato, mas sua implementação emite um histórico escolar.

#### Classe EmissorCertificadoConclusao

```csharp
public class EmissorCertificadoConclusao : IEmissorDeDocumento
{
    public void Emitir(string nomeEstudante)
    {
        Console.WriteLine($"Certificado de conclusão emitido para: {nomeEstudante}.");
    }
}
```

Essa classe emite um certificado de conclusão.

### Teste no Program.cs

```csharp
IEmissorDeDocumento emissor = new EmissorDeclaracaoMatricula();
emissor.Emitir("Mariana");

emissor = new EmissorHistoricoEscolar();
emissor.Emitir("Mariana");

emissor = new EmissorCertificadoConclusao();
emissor.Emitir("Mariana");
```

### Resultado esperado

```text
Declaração de matrícula: Mariana está regularmente matriculada.
Histórico escolar emitido para: Mariana.
Certificado de conclusão emitido para: Mariana.
```

### Comentário da solução

A variável `emissor` é do tipo `IEmissorDeDocumento`.

Isso significa que ela pode receber qualquer objeto que implemente essa interface.

Primeiro, ela recebe um `EmissorDeclaracaoMatricula`.

Depois, recebe um `EmissorHistoricoEscolar`.

Por fim, recebe um `EmissorCertificadoConclusao`.

O método chamado é sempre `Emitir`, mas o comportamento executado muda conforme a classe concreta.

### Como validar

A validação pode ser feita observando três pontos.

Primeiro, o projeto deve compilar sem erros. Se alguma classe não implementar corretamente o método `Emitir`, o compilador indicará que o contrato não foi cumprido.

Segundo, cada chamada a `emissor.Emitir("Mariana")` deve produzir uma mensagem diferente, de acordo com o tipo concreto usado no momento.

Terceiro, a variável deve permanecer declarada como `IEmissorDeDocumento`, mostrando que o código depende do contrato e não de uma classe específica.

### Possíveis erros

Um erro comum seria esquecer o parâmetro:

```csharp
public void Emitir()
{
    Console.WriteLine("Documento emitido.");
}
```

Esse método não cumpre a interface porque a interface exige:

```csharp
void Emitir(string nomeEstudante);
```

Outro erro seria declarar o método como `private`:

```csharp
private void Emitir(string nomeEstudante)
{
    Console.WriteLine(nomeEstudante);
}
```

Esse método não satisfaz o contrato público da interface.

A forma correta é:

```csharp
public void Emitir(string nomeEstudante)
{
    Console.WriteLine(nomeEstudante);
}
```

## 18. Erros comuns e dúvidas frequentes

### Erro 1: esquecer de implementar um método da interface

Se a interface define um método, toda classe que implementa essa interface precisa fornecer esse método.

Interface:

```csharp
public interface IExportador
{
    void Exportar(string conteudo);
}
```

Classe incorreta:

```csharp
public class ExportadorPdf : IExportador
{
}
```

O erro ocorre porque `ExportadorPdf` não implementou `Exportar`.

Correção:

```csharp
public class ExportadorPdf : IExportador
{
    public void Exportar(string conteudo)
    {
        Console.WriteLine($"Exportando em PDF: {conteudo}");
    }
}
```

### Erro 2: alterar a assinatura do método

Se a interface exige:

```csharp
void Exportar(string conteudo);
```

A classe não pode implementar:

```csharp
public void Exportar(int conteudo)
```

nem:

```csharp
public string Exportar(string conteudo)
```

nem:

```csharp
public void Exportar()
```

Todas essas assinaturas são diferentes da assinatura exigida.

### Erro 3: usar método privado na implementação

Métodos definidos por interface precisam estar acessíveis pela referência da interface.

Portanto, a implementação deve ser pública:

```csharp
public void Exportar(string conteudo)
{
    Console.WriteLine(conteudo);
}
```

Se o método for `private`, outras partes do código não poderão chamá-lo pela interface.

### Erro 4: criar interface grande demais

Interfaces muito grandes podem obrigar classes a implementar métodos que não pertencem ao seu papel.

Em vez de uma interface ampla e confusa, prefira contratos menores e focados.

Ruim:

```csharp
public interface ISistemaAcademicoCompleto
{
    void CadastrarEstudante(string nome);
    void EmitirHistorico(string estudante);
    void GerarFolhaPagamento();
    void EnviarEmail(string destinatario, string mensagem);
}
```

Melhor:

```csharp
public interface IEmissorDeHistorico
{
    void EmitirHistorico(string estudante);
}
```

```csharp
public interface INotificador
{
    void Enviar(string destinatario, string mensagem);
}
```

Essa separação deixa o código mais claro e evita dependências desnecessárias.

### Dúvida: interface é a mesma coisa que classe?

Não.

Uma classe pode ter atributos, métodos com implementação e estado interno.

Uma interface define um contrato. Ela especifica o que uma classe deve oferecer, sem definir necessariamente como cada comportamento será executado.

### Dúvida: posso criar objeto diretamente de uma interface?

Não é possível instanciar uma interface diretamente assim:

```csharp
IExportador exportador = new IExportador();
```

Isso está incorreto porque uma interface não é uma implementação concreta.

O correto é criar uma classe que implemente a interface:

```csharp
IExportador exportador = new ExportadorCsv();
```

### Dúvida: por que não usar sempre a classe concreta?

Usar a classe concreta diretamente pode ser suficiente em exemplos simples.

Porém, em sistemas que precisam trocar implementações, testar comportamentos, organizar responsabilidades ou reduzir dependência entre partes do código, usar a interface como tipo torna o código mais flexível.

## 19. Checklist explicado de aprendizagem e implementação

### Verifique se a interface representa um comportamento claro

A interface deve expressar uma responsabilidade compreensível, como exportar, calcular desconto, autenticar ou emitir documento.

Isso importa porque uma interface confusa gera implementações confusas.

Para validar, leia o nome da interface e seus métodos. Eles devem formar uma ideia coerente. Por exemplo, `IExportador` com método `Exportar` é coerente.

Se esse cuidado faltar, a interface pode misturar responsabilidades e dificultar a manutenção.

### Verifique se o nome da interface segue uma convenção clara

Em C#, é comum iniciar nomes de interfaces com `I`, como `IExportador`.

Isso importa porque facilita a leitura do código e ajuda outros desenvolvedores a reconhecerem rapidamente que aquele tipo é um contrato.

Para validar, observe se o nome começa com `I` e se descreve um papel, não uma ação isolada confusa.

Se esse cuidado faltar, o código ainda pode funcionar, mas ficará menos legível.

### Verifique se todos os métodos da interface foram implementados

Toda classe que implementa uma interface precisa fornecer todos os membros exigidos.

Isso importa porque o contrato precisa ser completo para que o código seja confiável.

Para validar, compile o projeto. O compilador acusará erro se algum membro obrigatório estiver ausente.

Se esse cuidado faltar, o código não compilará.

### Verifique se a assinatura dos métodos está correta

Nome, retorno, parâmetros e ordem dos parâmetros precisam corresponder ao que foi definido na interface.

Isso importa porque pequenas diferenças criam métodos diferentes.

Para validar, compare a assinatura da interface com a assinatura implementada na classe.

Se esse cuidado faltar, a classe não cumprirá o contrato.

### Verifique se os métodos implementados estão públicos

Os métodos da interface precisam ser acessíveis por meio da referência da interface.

Isso importa porque o código externo chamará os métodos usando o tipo do contrato.

Para validar, confirme se a implementação usa `public`.

Se esse cuidado faltar, o contrato não será atendido corretamente.

### Verifique se a variável pode ser declarada pelo tipo da interface

Uma das principais vantagens da interface é permitir código baseado em contrato.

Isso importa porque reduz dependência em relação a uma classe específica.

Para validar, tente declarar:

```csharp
IExportador exportador = new ExportadorCsv();
```

Depois troque a implementação:

```csharp
exportador = new ExportadorJson();
```

Se a troca funcionar sem alterar o restante da lógica, o contrato está sendo usado corretamente.

### Verifique se a interface não está grande demais

Interfaces devem ser focadas.

Isso importa porque classes não devem ser obrigadas a implementar comportamentos que não fazem parte de seu papel.

Para validar, pergunte se todos os métodos da interface pertencem à mesma responsabilidade.

Se esse cuidado faltar, o sistema pode ficar rígido, acoplado e difícil de evoluir.

## 20. Síntese final

Interface é um contrato de comportamento.

Ela define o que uma classe precisa oferecer, mas não determina como o comportamento será executado.

Em C#, uma interface é declarada com a palavra-chave `interface`.

Por convenção, nomes de interfaces costumam começar com a letra `I`.

Uma classe implementa uma interface usando `:`.

Quando uma classe implementa uma interface, ela precisa implementar todos os membros exigidos.

A assinatura dos métodos precisa ser compatível com o contrato.

A variável pode ser declarada com o tipo da interface, permitindo que diferentes classes concretas sejam usadas de forma intercambiável.

Interfaces ajudam a separar contrato e implementação.

Essa separação torna o código mais flexível, organizado e preparado para mudanças.

---

## Conclusão

O ponto mais importante não é apenas saber escrever uma interface em C#.

O essencial é compreender que uma interface permite separar o que precisa ser feito de como será feito.

Quando você cria uma interface como `IExportador`, está dizendo ao sistema: qualquer classe que cumprir este contrato poderá ser usada como exportador.

Depois disso, classes como `ExportadorCsv`, `ExportadorJson`, `ExportadorHtml` ou `ExportadorTexto` podem executar o mesmo comportamento de formas diferentes.

Essa lógica permite construir sistemas mais flexíveis, porque o código passa a depender de contratos estáveis em vez de depender diretamente de implementações específicas.
