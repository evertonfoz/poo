# Mini Projeto com Interfaces e Serviços em C#: emissão de certificados acadêmicos

## Objetivo do material

Neste material, você aprenderá a concluir um mini projeto em C# para emissão de certificados acadêmicos usando entidades, interfaces, implementações concretas, serviço de aplicação e `Program.cs`.

O foco é entender como organizar um sistema em partes com responsabilidades claras. Ao final, você saberá:

* criar um serviço que depende de interfaces;
* receber dependências pelo construtor;
* coordenar um caso de uso completo;
* validar regras de negócio antes de executar ações;
* trocar implementações sem alterar o serviço;
* expandir o projeto criando novas classes concretas;
* testar cenários válidos e inválidos.

O conteúdo parte da estrutura apresentada no arquivo-base, que conclui um mini projeto de emissão de certificados acadêmicos em C# com `CertificadoService.cs`, `Program.cs`, testes e expansão por novas implementações. 

---

# 1. Contextualização do problema

Imagine um sistema acadêmico simples. Um aluno conclui um curso e precisa receber um certificado. Para isso, o sistema deve executar várias etapas:

1. receber os dados do aluno;
2. receber os dados do curso;
3. verificar se o aluno concluiu o curso;
4. verificar se o curso atende às regras mínimas para emissão;
5. criar o certificado;
6. emitir o certificado em algum formato;
7. registrar a emissão;
8. notificar o aluno.

Um erro comum seria colocar todas essas responsabilidades em uma única classe. Isso tornaria o sistema difícil de manter, testar e expandir.

A solução apresentada neste projeto é separar responsabilidades:

* as **entidades** representam dados importantes do domínio;
* as **interfaces** definem contratos de comportamento;
* as **implementações concretas** executam esses contratos;
* o **serviço** coordena o caso de uso;
* o **Program.cs** monta os objetos e executa o sistema.

Essa organização reduz o acoplamento. Isso significa que o serviço não fica preso a detalhes como “emitir em PDF”, “emitir em HTML”, “registrar no console” ou “enviar e-mail”. Ele apenas conhece os contratos que precisa usar.

A estrutura esperada do projeto é:

```text
MiniProjetoCertificados

|   |— Aluno.cs

|   |— Certificado.cs
|
|— Interfaces
|   |— IEmissorDeCertificado.cs

|   |— INotificador.cs
|
|— Implementacoes
|   |— EmissorCertificadoPdf.cs

|   |— EmissorCertificadoTexto.cs
|   |— EmailNotificador.cs
|   |— SmsNotificador.cs
|   |— ConsoleNotificador.cs
|   |— RegistroCertificadoConsole.cs

|   |— RegistroCertificadoArquivo.cs

|   |— CertificadoService.cs
```

Essa separação ajuda o aluno a enxergar onde cada tipo de código deve ficar.

A pasta `Entidades` contém classes que representam conceitos do domínio, como aluno, curso e certificado.

A pasta `Interfaces` contém contratos. Um contrato define o que uma classe deve fazer, mas não define como ela fará.

A pasta `Implementacoes` contém classes concretas que realizam comportamentos específicos, como emitir certificado em PDF ou enviar uma notificação por SMS.

A pasta `Servicos` contém a classe que coordena o processo principal.

O arquivo `Program.cs` é o ponto de entrada do sistema. Nele, as implementações concretas são escolhidas e conectadas ao serviço.

# 3. Conceitos fundamentais

## 3.1 Entidade

Uma entidade representa algo importante para o sistema. Neste projeto, temos três entidades principais:

* `Aluno`;
* `Curso`;
* `Certificado`.

A entidade não deve ser apenas um agrupamento de variáveis soltas. Ela deve proteger seus próprios dados e representar corretamente uma parte do domínio.

Por exemplo, um aluno tem nome, contato e uma indicação de conclusão de curso. Um curso tem nome e carga horária. Um certificado relaciona um aluno a um curso e registra dados da emissão.

---

## 3.2 Interface

Uma interface define um contrato. Ela informa quais métodos uma classe precisa implementar, mas não determina a forma de execução.

Exemplo:

```csharp
public interface IEmissorDeCertificado
{
    void Emitir(Certificado certificado);
}
```

Essa interface diz que qualquer emissor de certificado precisa ter um método chamado `Emitir`, que recebe um `Certificado`.

Ela não diz se o certificado será emitido em PDF, HTML, texto ou outro formato. Essa decisão fica para as classes concretas.

---

## 3.3 Implementação concreta

Uma implementação concreta é uma classe que cumpre uma interface.

Por exemplo:

```csharp
public class EmissorCertificadoPdf : IEmissorDeCertificado
{
    public void Emitir(Certificado certificado)
    {
        Console.WriteLine("Emitindo certificado em PDF...");
        Console.WriteLine(certificado.ObterResumo());
    }
}
```

Essa classe implementa o contrato `IEmissorDeCertificado`. Ela escolhe uma forma específica de emitir: PDF simulado no console.

Outra classe pode implementar a mesma interface de outra maneira:

```csharp
public class EmissorCertificadoHtml : IEmissorDeCertificado
{
    public void Emitir(Certificado certificado)
    {
        Console.WriteLine("Emitindo certificado em HTML...");
        Console.WriteLine($"<h1>Certificado de {certificado.Aluno.Nome}</h1>");
        Console.WriteLine($"<p>Curso: {certificado.Curso.Nome}</p>");
    }
}
```

As duas classes cumprem o mesmo contrato, mas executam o comportamento de formas diferentes.

---

## 3.4 Serviço

Um serviço coordena um caso de uso. Neste projeto, o serviço principal é `CertificadoService`.

Ele não deve ser responsável por saber como gerar PDF, como enviar e-mail ou como registrar em memória. Ele apenas organiza o fluxo:

1. validar aluno;
2. validar curso;
3. verificar conclusão;
4. verificar carga horária;
5. criar certificado;
6. chamar o emissor;
7. chamar o registrador;
8. chamar o notificador;
9. retornar o certificado.

O serviço é o centro da lógica do caso de uso, mas não deve concentrar todos os detalhes técnicos.

---

## 3.5 Injeção de dependência pelo construtor

A classe `CertificadoService` recebe suas dependências pelo construtor:

```csharp
public CertificadoService(
    IEmissorDeCertificado emissorDeCertificado,
    IRegistroDeCertificado registroDeCertificado,
    INotificador notificador)
```

Isso significa que ela não cria diretamente um `EmissorCertificadoPdf`, um `RegistroCertificadoConsole` ou um `EmailNotificador`.

Em vez disso, alguém de fora entrega esses objetos ao serviço.

Essa escolha traz flexibilidade. O mesmo serviço pode funcionar com PDF, HTML, texto, e-mail, SMS, console, memória ou arquivo, desde que as classes entregues implementem as interfaces esperadas.

---

# 4. Diferenças conceituais importantes

## Interface não é implementação

A interface define o que deve existir. A implementação define como aquilo será feito.

Exemplo:

```csharp
public interface INotificador
{
    void Enviar(string destinatario, string mensagem);
}
```

Essa interface diz que existe uma operação de envio de notificação. Porém, ela não sabe se a mensagem será enviada por e-mail, SMS ou console.

Já uma classe concreta faz a execução:

```csharp
public class EmailNotificador : INotificador
{
    public void Enviar(string destinatario, string mensagem)
    {
        Console.WriteLine($"Enviando e-mail para {destinatario}: {mensagem}");
    }
}
```

---

## Serviço não é entidade

A entidade representa dados e regras ligadas diretamente ao objeto do domínio.

O serviço coordena uma operação maior.

Por exemplo, `Aluno` pode saber marcar um curso como concluído. Mas o fluxo completo de emissão de certificado envolve aluno, curso, certificado, emissor, registro e notificação. Por isso, esse fluxo pertence ao serviço.

---

## Program.cs não é regra de negócio

O `Program.cs` monta e executa o sistema. Ele escolhe quais implementações serão usadas.

A regra que impede emissão para aluno sem conclusão não deve ficar espalhada no `Program.cs`. Ela deve ficar no serviço, porque faz parte do caso de uso de emissão de certificado.

# 5. Código das entidades

## 5.1 Classe Aluno

```csharp
namespace MiniProjetoCertificados.Entidades;

public class Aluno
{
    public string Nome { get; private set; }
    public string Contato { get; private set; }
    public bool CursoConcluido { get; private set; }

    public Aluno(string nome, string contato, bool cursoConcluido)
    {
        if (string.IsNullOrWhiteSpace(nome))
        {
            throw new ArgumentException("O nome do aluno é obrigatório.", nameof(nome));
        }

        if (string.IsNullOrWhiteSpace(contato))
        {
            throw new ArgumentException("O contato do aluno é obrigatório.", nameof(contato));
        }

        Nome = nome;
        Contato = contato;
        CursoConcluido = cursoConcluido;
    }

    public void MarcarCursoComoConcluido()
    {
        CursoConcluido = true;
    }
}
```

A classe `Aluno` usa `private set` para impedir que qualquer parte do sistema altere seus dados diretamente. Isso protege o estado do objeto.

O método `MarcarCursoComoConcluido()` permite mudar o estado de forma controlada. Esse método é útil quando o aluno é criado inicialmente como não concluinte, mas depois finaliza o curso.

---

## 5.2 Classe Curso

```csharp
namespace MiniProjetoCertificados.Entidades;

public class Curso
{
    public string Nome { get; private set; }
    public int CargaHoraria { get; private set; }

    public Curso(string nome, int cargaHoraria)
    {
        if (string.IsNullOrWhiteSpace(nome))
        {
            throw new ArgumentException("O nome do curso é obrigatório.", nameof(nome));
        }

        if (cargaHoraria <= 0)
        {
            throw new ArgumentException("A carga horária deve ser maior que zero.", nameof(cargaHoraria));
        }

        Nome = nome;
        CargaHoraria = cargaHoraria;
    }
}
```

A classe `Curso` valida dados básicos: o nome precisa existir e a carga horária precisa ser maior que zero.

A regra de carga horária mínima para emissão do certificado será colocada no serviço. Isso acontece porque uma carga horária de 10 horas pode ser válida para existir como curso, mas insuficiente para emitir certificado dentro da regra do sistema.

---

## 5.3 Classe Certificado

```csharp
namespace MiniProjetoCertificados.Entidades;

public class Certificado
{
    public Aluno Aluno { get; private set; }
    public Curso Curso { get; private set; }
    public DateTime DataEmissao { get; private set; }
    public string CodigoVerificacao { get; private set; }

    public Certificado(Aluno aluno, Curso curso)
    {
        Aluno = aluno ?? throw new ArgumentNullException(nameof(aluno));
        Curso = curso ?? throw new ArgumentNullException(nameof(curso));
        DataEmissao = DateTime.Now;
        CodigoVerificacao = Guid.NewGuid().ToString("N")[..8].ToUpper();
    }

    public string ObterResumo()
    {
        return $"Certificado {CodigoVerificacao} emitido para {Aluno.Nome}, " +
               $"referente ao curso {Curso.Nome}, com carga horária de {Curso.CargaHoraria}h, " +
               $"em {DataEmissao:dd/MM/yyyy}.";
    }
}
```

A classe `Certificado` recebe um aluno e um curso. Ela também define automaticamente a data de emissão e um código de verificação.

O método `ObterResumo()` centraliza a forma de apresentar os dados principais do certificado.

# 8. Criando o serviço CertificadoService

O serviço é responsável por coordenar o fluxo principal do sistema.

Ele recebe três dependências:

* `IEmissorDeCertificado`;
* `IRegistroDeCertificado`;
* `INotificador`.

Essas dependências são recebidas por interface, não por classes concretas.

```csharp
using MiniProjetoCertificados.Entidades;
using MiniProjetoCertificados.Interfaces;

namespace MiniProjetoCertificados.Servicos;

public class CertificadoService
{
    private readonly IEmissorDeCertificado _emissorDeCertificado;
    private readonly IRegistroDeCertificado _registroDeCertificado;
    private readonly INotificador _notificador;

    public CertificadoService(
        IEmissorDeCertificado emissorDeCertificado,
        IRegistroDeCertificado registroDeCertificado,
        INotificador notificador)
    {
        _emissorDeCertificado = emissorDeCertificado
            ?? throw new ArgumentNullException(nameof(emissorDeCertificado));

        _registroDeCertificado = registroDeCertificado
            ?? throw new ArgumentNullException(nameof(registroDeCertificado));

        _notificador = notificador
            ?? throw new ArgumentNullException(nameof(notificador));
    }

    public Certificado EmitirCertificado(Aluno aluno, Curso curso)
    {
        if (aluno is null)
        {
            throw new ArgumentNullException(nameof(aluno));
        }

        if (curso is null)
        {
            throw new ArgumentNullException(nameof(curso));
        }

        if (!aluno.CursoConcluido)
        {
            throw new InvalidOperationException(
                "O certificado não pode ser emitido porque o aluno ainda não concluiu o curso.");
        }

        if (curso.CargaHoraria < 20)
        {
            throw new InvalidOperationException(
                "O certificado só pode ser emitido para cursos com pelo menos 20 horas.");
        }

        Certificado certificado = new Certificado(aluno, curso);

        _emissorDeCertificado.Emitir(certificado);
        _registroDeCertificado.Registrar(certificado);

        string mensagem = $"Seu certificado do curso {curso.Nome} foi emitido com sucesso.";
        _notificador.Enviar(aluno.Contato, mensagem);

        return certificado;
    }
}
```

## Análise do construtor

O construtor usa o operador `??`:

```csharp
_emissorDeCertificado = emissorDeCertificado
    ?? throw new ArgumentNullException(nameof(emissorDeCertificado));
```

Esse código significa: se `emissorDeCertificado` não for nulo, armazene a dependência. Se for nulo, lance uma exceção.

Essa validação é importante porque o serviço não pode funcionar sem suas dependências. Se o erro for identificado logo na criação do serviço, fica mais fácil entender o problema.

---

## Análise do método EmitirCertificado

O método `EmitirCertificado` executa o caso de uso completo.

Primeiro, ele valida se `aluno` e `curso` existem. Isso evita erros posteriores, como tentar acessar propriedades de um objeto nulo.

Depois, ele verifica se o aluno concluiu o curso. Se não concluiu, o certificado não pode ser emitido.

Em seguida, verifica se a carga horária do curso é de pelo menos 20 horas. Essa regra impede emissão para cursos muito curtos.

Somente depois das validações o certificado é criado.

Depois da criação, o serviço chama os comportamentos externos:

```csharp
_emissorDeCertificado.Emitir(certificado);
_registroDeCertificado.Registrar(certificado);
_notificador.Enviar(aluno.Contato, mensagem);
```

Observe que o serviço não sabe qual classe concreta está por trás dessas chamadas. Ele apenas confia nos contratos.

# 9. Montando o primeiro cenário no Program.cs

Neste cenário, o sistema usa:

* emissão em PDF;
* registro no console;
* notificação por e-mail.

```csharp
using MiniProjetoCertificados.Entidades;
using MiniProjetoCertificados.Implementacoes;
using MiniProjetoCertificados.Interfaces;
using MiniProjetoCertificados.Servicos;

IEmissorDeCertificado emissor = new EmissorCertificadoPdf();
IRegistroDeCertificado registro = new RegistroCertificadoConsole();
INotificador notificador = new EmailNotificador();

CertificadoService certificadoService = new CertificadoService(
    emissor,
    registro,
    notificador
);

Aluno aluno = new Aluno("Beatriz", "beatriz@email.com", true);
Curso curso = new Curso("Programação Orientada a Objetos em C#", 80);

try
{
    Certificado certificado = certificadoService.EmitirCertificado(aluno, curso);

    Console.WriteLine("Processo concluído.");
    Console.WriteLine(certificado.ObterResumo());
}
catch (Exception ex)
{
    Console.WriteLine($"Erro: {ex.Message}");
}
```

## Resultado esperado

O processo deve ser concluído com sucesso, porque:

* o aluno não é nulo;
* o curso não é nulo;
* o aluno concluiu o curso;
* o curso tem 80 horas, acima do mínimo de 20 horas;
* todas as dependências foram fornecidas ao serviço.

A saída será semelhante a:

```text
Emitindo certificado em PDF...
Certificado 1A2B3C4D emitido para Beatriz, referente ao curso Programação Orientada a Objetos em C#, com carga horária de 80h, em 18/06/2026.
Registrando certificado no console...
Certificado 1A2B3C4D emitido para Beatriz, referente ao curso Programação Orientada a Objetos em C#, com carga horária de 80h, em 18/06/2026.
Enviando e-mail para beatriz@email.com: Seu certificado do curso Programação Orientada a Objetos em C# foi emitido com sucesso.
Processo concluído.
Certificado 1A2B3C4D emitido para Beatriz, referente ao curso Programação Orientada a Objetos em C#, com carga horária de 80h, em 18/06/2026.
```

O código de verificação e a data podem variar, porque são gerados durante a execução.

# 11. Testando aluno sem conclusão de curso

# 13. Regra de carga horária mínima

A regra adicionada ao serviço define que o certificado só pode ser emitido para cursos com pelo menos 20 horas.

```csharp
if (curso.CargaHoraria < 20)
{
    throw new InvalidOperationException(
        "O certificado só pode ser emitido para cursos com pelo menos 20 horas.");
}
```

Essa validação deve acontecer antes da criação do certificado.

A ordem recomendada é:

1. validar se aluno é nulo;
2. validar se curso é nulo;
3. verificar se o aluno concluiu o curso;
4. verificar se o curso tem pelo menos 20 horas;
5. criar certificado;
6. emitir;
7. registrar;
8. notificar.

Essa ordem evita processamento desnecessário e mantém o fluxo lógico.

# 18. Aplicação prática resolvida

## Cenário

Uma instituição quer emitir certificados para alunos que concluíram cursos. O sistema precisa emitir o certificado em texto, registrar a emissão simulando um arquivo e notificar o aluno pelo console.

## Objetivo

Montar o sistema usando as seguintes implementações:

* `EmissorCertificadoTexto`;
* `RegistroCertificadoArquivo`;
* `ConsoleNotificador`.

O aluno deve ter concluído um curso com carga horária válida.

---

## Solução completa

```csharp
using MiniProjetoCertificados.Entidades;
using MiniProjetoCertificados.Implementacoes;
using MiniProjetoCertificados.Interfaces;
using MiniProjetoCertificados.Servicos;

IEmissorDeCertificado emissor = new EmissorCertificadoTexto();
IRegistroDeCertificado registro = new RegistroCertificadoArquivo();
INotificador notificador = new ConsoleNotificador();

CertificadoService certificadoService = new CertificadoService(
    emissor,
    registro,
    notificador

catch (Exception ex)
{
    Console.WriteLine($"Erro: {ex.Message}");
}
```

## Comentário da solução

O `Program.cs` cria três objetos concretos, mas armazena cada um em uma variável do tipo da interface:

```csharp
IEmissorDeCertificado emissor = new EmissorCertificadoTexto();
IRegistroDeCertificado registro = new RegistroCertificadoArquivo();
INotificador notificador = new ConsoleNotificador();
```

Isso significa que o restante do código não fica preso à classe concreta.

Depois, essas dependências são entregues ao serviço:

```csharp
CertificadoService certificadoService = new CertificadoService(
    emissor,
    registro,
    notificador
);
```

Quando o método `EmitirCertificado` é chamado, o serviço executa as validações. Como o aluno concluiu o curso e a carga horária é de 32 horas, o certificado pode ser emitido.

# 19. Respostas comentadas para consolidação

## Qual classe coordena o fluxo de emissão?

A classe que coordena o fluxo é `CertificadoService`.

Ela recebe aluno e curso, valida as regras de negócio, cria o certificado, chama o emissor, registra a emissão e envia a notificação.

Ela não deve executar diretamente todos os detalhes técnicos. Sua responsabilidade principal é organizar o caso de uso.

---

## O serviço depende de classes concretas ou de interfaces?

O serviço depende de interfaces.

Ele usa:

* `IEmissorDeCertificado`;
* `IRegistroDeCertificado`;
* `INotificador`.

A vantagem é que o serviço pode trabalhar com diferentes implementações sem ser alterado.

---

## Por que as dependências são recebidas pelo construtor?

As dependências são recebidas pelo construtor para que o serviço seja montado de fora para dentro.

Isso permite trocar implementações com facilidade e também facilita testes, porque é possível entregar objetos simulados ao serviço.

Além disso, o construtor deixa claro quais dependências são obrigatórias para a classe funcionar.

---

## O que precisa ser alterado para trocar PDF por HTML ou e-mail por SMS?

A alteração deve ocorrer apenas no `Program.cs`, na montagem das dependências.

Para trocar PDF por HTML:

```csharp
IEmissorDeCertificado emissor = new EmissorCertificadoHtml();
```

Para trocar e-mail por SMS:

```csharp
INotificador notificador = new SmsNotificador();
```

O `CertificadoService` não precisa ser alterado.

---

## Qual é a vantagem de separar entidades, interfaces, implementações e serviço?

A separação melhora a organização e reduz o acoplamento.

As entidades representam os dados importantes do domínio.

As interfaces definem os contratos.

As implementações executam os contratos de formas específicas.

O serviço coordena o caso de uso.

O `Program.cs` monta o sistema e escolhe as implementações concretas.

Essa divisão torna o projeto mais claro, testável e preparado para mudanças.

# 20. Erros comuns e dúvidas frequentes

## Erro 1: colocar todas as regras no Program.cs

O `Program.cs` deve montar e executar o sistema. Ele não deve concentrar regras como “aluno precisa concluir o curso” ou “curso precisa ter no mínimo 20 horas”.

Essas regras pertencem ao serviço, porque fazem parte do processo de emissão.

---

## Erro 2: criar implementações concretas dentro do serviço

Evite este padrão:

```csharp
private readonly INotificador _notificador = new EmailNotificador();
```

Isso prende o serviço ao e-mail. Se depois o sistema precisar usar SMS, será necessário alterar o serviço.

O melhor é receber a dependência pelo construtor.

---

## Erro 3: esquecer validações antes da emissão

O serviço deve validar antes de emitir.

Se a emissão acontecer antes da validação, o sistema pode gerar certificado para aluno sem conclusão ou para curso sem carga horária mínima.

A ordem correta evita efeitos indesejados.

---

## Erro 4: tratar interface como se fosse classe concreta

A interface não é instanciada diretamente:

```csharp
IEmissorDeCertificado emissor = new IEmissorDeCertificado();
```

Esse código é inválido.

O correto é instanciar uma classe que implementa a interface:

```csharp
IEmissorDeCertificado emissor = new EmissorCertificadoPdf();
```

---

## Erro 5: criar uma nova implementação e alterar o serviço sem necessidade

Se uma nova classe implementa a interface correta, o serviço não precisa ser alterado.

Por exemplo, ao criar `EmissorCertificadoTexto`, basta trocar a montagem no `Program.cs`.

# 21. Checklist explicado

## Verifique se as entidades representam o domínio corretamente

As classes `Aluno`, `Curso` e `Certificado` devem representar informações importantes do sistema. Isso importa porque o serviço depende dessas entidades para executar o caso de uso. Para validar, confira se cada entidade possui propriedades coerentes e construtores com validações básicas. Se essa etapa faltar, o sistema pode aceitar dados inválidos desde o início.

## Verifique se as interfaces definem contratos claros

As interfaces devem indicar comportamentos esperados, como emitir, registrar e notificar. Isso importa porque o serviço trabalha com esses contratos. Para validar, confira se `IEmissorDeCertificado`, `IRegistroDeCertificado` e `INotificador` possuem métodos simples e objetivos. Se os contratos forem confusos, as implementações também ficarão inconsistentes.

## Verifique se o serviço depende de interfaces, não de classes concretas

O `CertificadoService` deve receber interfaces no construtor. Isso importa porque permite trocar PDF por HTML, e-mail por SMS ou console por arquivo sem alterar o serviço. Para validar, observe os tipos dos parâmetros do construtor. Se aparecerem classes concretas como `EmissorCertificadoPdf` no construtor do serviço, há acoplamento excessivo.

## Verifique se as dependências são validadas no construtor

O serviço deve impedir dependências nulas. Isso importa porque ele não consegue funcionar sem emissor, registrador e notificador. Para validar, confira o uso de `ArgumentNullException`. Se essa validação faltar, o erro pode aparecer mais tarde de forma menos clara.

## Verifique se as regras de negócio estão antes das ações

Antes de emitir, registrar ou notificar, o serviço deve validar aluno, curso, conclusão e carga horária. Isso importa porque evita que o sistema execute ações indevidas. Para validar, leia a ordem do método `EmitirCertificado`. Se a emissão acontecer antes das validações, o fluxo está incorreto.

## Verifique se novas implementações cumprem as interfaces

Toda nova classe concreta deve implementar a interface correspondente. Isso importa porque o serviço só reconhece os contratos. Para validar, confira se a classe possui a declaração correta, como `: IEmissorDeCertificado`, `: IRegistroDeCertificado` ou `: INotificador`. Se a classe não implementar a interface, ela não poderá ser usada no lugar esperado.

## Verifique se o Program.cs é o ponto de montagem

O `Program.cs` deve escolher quais implementações concretas serão usadas. Isso importa porque concentra a configuração do cenário em um único local. Para validar, veja se as linhas com `new EmissorCertificadoPdf()`, `new RegistroCertificadoConsole()` e `new EmailNotificador()` estão fora do serviço. Se essas criações estiverem dentro do serviço, a troca de comportamento ficará mais difícil.

## Verifique se os cenários inválidos são testados

O sistema deve ser testado com aluno sem conclusão e curso com menos de 20 horas. Isso importa porque as regras de negócio precisam ser comprovadas. Para validar, execute cenários que gerem erro esperado. Se apenas cenários válidos forem testados, problemas nas validações podem passar despercebidos.
