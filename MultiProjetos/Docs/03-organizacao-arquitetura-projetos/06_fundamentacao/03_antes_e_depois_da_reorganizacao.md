# Antes e Depois da Reorganizacao

## Antes

1. Classes de dominio no root do projeto.
2. Pouca indicacao de onde cada novo arquivo deveria nascer.
3. Risco de crescimento desordenado.

## Depois

1. Domain dividido por tipo arquitetural (entities, value objects e enums).
2. Application, Console e Blazor com pastas preparadas para a proxima fase.
3. Estrutura mais previsivel para evolucao do projeto.

## Impacto didatico

1. O aluno entende a funcao de cada camada de forma visual.
2. O professor consegue orientar com menos ambiguidade.
3. A manutencao fica mais simples ao longo das sessoes.
